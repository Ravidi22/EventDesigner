## Design Context

- **[PRODUCT.md](PRODUCT.md)** — strategy. Register: **product**. Platform: **web** (Next.js). A quiet operational studio for event designers; the tool recedes so the designer's work is the color. Anti-references: generic SaaS dashboard, dark-mode terminal, consumer-flashy, cluttered CRM. RTL/Hebrew-first, WCAG AA, B&W-print-legible outputs.
- **[DESIGN.md](DESIGN.md)** — visual system ("EvE" / The Lit Studio, imported from the claude.ai/design project): lavender-grey plane with white cards, indigo-violet accent `#6D55BD`, a warm mesh gradient reserved for brand moments (at most one saturated surface + one filled CTA per screen), Assistant for all Hebrew/UI, Urbanist for the `Eve.` wordmark only, Space Grotesk for overlines only. Pill geometry (8/14/22/pill), violet-cast shadows. Every gradient wears grain; no text sits on the mesh without a scrim; text always uses the darkened semantic inks, never the brand fills.
- Run `/impeccable <command>` for design work; re-run `/impeccable document` after the first real UI build to capture actual tokens.

## Design System Guidelines

Locked in after iterative passes on the sidebar (`components/app-shell.tsx`, `components/venue-switcher.tsx`) — apply these exactly to that surface and to any new nav/card/dropdown sub-component. Written against this project's own `@theme` tokens (`app/globals.css`) rather than raw Tailwind defaults or arbitrary hex, so it can't drift from `DESIGN.md`'s token scale.

- **Border radius — uniform `rounded-md` (14px):** the sidebar `<aside>` (floating card, `p-3`/`gap-3` gutter off the viewport edge instead of flush), nav items, the profile card, and the venue switcher's trigger/panel all share this one radius now — not a tiered "outer bigger, inner smaller" scheme (an earlier pass tried that; a precise re-spec explicitly pinned every one of these to 14px, so it's uniform). **Never `rounded-full`/`rounded-pill`** on a nav item, card, or dropdown panel — at typical sidebar row heights a large radius clips to a full pill regardless of the class name.
- **Sidebar typography:** nav labels `text-sm` (14px), `font-semibold` (600) inactive in `text-muted` (`#7C7889`), **`font-bold` (700)** + `text-accent` when active — active nav *is* meant to be fully bold here, per an exact re-spec; don't soften it back to `font-semibold`.
- **Icon sizing:** standard nav icons are `h-[18px] w-[18px]`, `strokeWidth={1.4}`.
- **Active navigation highlight:** background `bg-accent-tint` (`#EFEAFB` — the closest token to specs asking for `#F3EEFF`/`#F4F0FC`/`purple-50`, all effectively the same near-white lavender); text and icon `text-accent` (`#6D55BD` — this project's one primary indigo-violet; do not introduce a second purple like `#6B46C1`). Do not use `bg-accent-wash` for the resting active state — it's reserved for the venue-switcher's own selected-option row.
- **Density:** nav items `px-3.5 py-[11px]`, `gap-3` icon-to-label, `gap-[3px]` between rows; profile card `p-[11px]`, `gap-[11px]`, with a `border-border` hairline and `bg-inset` (not `bg-accent-tint` — that's reserved for its hover state now).
- **Sidebar width:** `w-[258px]` expanded (an exact-pixel re-spec, not the Tailwind `w-64`/256px step), `w-[96px]` collapsed.
- **Sidebar wordmark:** collapsed keeps the full "Eve." wordmark small and centered (`text-[30px]`, `tone="gradient"` — unchanged, out of scope for the pixel re-spec below); expanded is `text-[28px]`, `tone="solid"` (flat `text-accent` word + `text-indigo-500` dot, no gradient fill), with a "EVENT STUDIO" caption underneath (`font-label` i.e. Space Grotesk, `10px`, `font-medium`, `tracking-[3px]`, `text-[#b6b2c4]`, `dir="ltr"`). This *is* a re-addition of a subtitle-like element under the logo after an earlier pass removed one — the two aren't the same thing (that one was Hebrew body copy; this is an English Space Grotesk overline, consistent with `DESIGN.md`'s "Space Grotesk for overlines only, Latin-only, never letter-spaced in Hebrew" rule) so don't delete it thinking it's the old subtitle come back. The 40px "large and bold" expanded size from an earlier pass has been superseded by this 28px exact re-spec — if asked to resize again, note that this number has flip-flopped several times already.
- **Card actions go behind a “…”, never a hover reveal.** `components/menu.tsx` is the shared trigger + panel (`rounded-md` panel, `rounded-sm` rows, `shadow-lifted`, Select's keyboard contract and `aria-activedescendant`). The dot is always visible, at muted weight, in the card's title row — the catalog card's hover-revealed עריכה/שכפול pair was replaced by it deliberately: buttons that fade in collide with whatever badge already occupies that corner, say nothing on a touch screen, and have nowhere to put a third action. Destructive rows are `danger: true` (alert ink) and go through `components/confirm-dialog.tsx` — a native `<dialog>` on the shared `.modal` scrim, ביטול first so `showModal()` cannot put focus on the destructive button. Every delete in a surface asks the same question: the catalog's menu and its edit drawer share one dialog, owned by the screen. A card whose menu is open must be lifted (`z-30`) while it is — the panel overhangs the next card, which is later in the DOM, and a hover `-translate-y` makes the card its own stacking context.
- **Every popup has a ✕, and it is `components/close-button.tsx`.** Dialogs, drawers and modals all close through the same round puck — `bg-accent-tint` circle, `text-accent` ✕, `accent-wash` on hover — visible at rest, never a ghost icon that only appears on hover. Don't hand-roll an `IconButton` + `X` in a popup header. In `ConfirmDialog` the ✕ is `tabIndex={-1}` so `showModal()` still lands focus on ביטול. **Destructive confirmations invert the usual weights:** ביטול is the filled `primary` button, and the destructive action is borderless alert-ink text.
- **Top bar:** matches the sidebar exactly — `rounded-md`, `shadow-floating`, same `gap-3` gutter. Page header shows the title only; **no subtitle line, on any page** — the per-route `sub()` descriptions were deliberately deleted from `TITLES` in `app-shell.tsx`, don't re-add them. The header search reuses the shared `SearchInput` component (`components/search-input.tsx`) as-is — same bordered white field, muted placeholder, and icon as every other search box in the app. An earlier pass gave it a custom borderless pill/`bg-bg` look; that was reverted in favor of just using `SearchInput` directly, so don't reintroduce a one-off style here.

## Working Rules

- **Verify before done:** `npm run typecheck` (tsc --noEmit; a Stop hook also runs this), `npm run check:actions`, `npm run check:costs` for anything touching money, and `npm run check:google` for the calendar sync. App: `npm run dev` → routes under `app/(app)/` + `/present`, `/meeting`, `/login`.
- **Backend seam:** every read and write goes through a module in `lib/<domain>/` — never a `localStorage` or `db()` call inside a component. **The migration is finished:** every domain is in Postgres behind `"use server"` actions (`lib/*/actions.ts`) — accounts and sessions, events, catalog, venues/structures/zones, studio members and venue grants, studio settings and the meeting flow, scheduled meetings, client portal, design documents, gallery, issued quotes, packing spares and exports, suppliers and expenses, and the production runway. Local DB: `docker compose up -d` then `npm run db:migrate`; schema is [lib/db/schema.ts](lib/db/schema.ts).
  - **The runway is derived; `confirmedAt` is the one thing typed.** `/production` (was `/gantt`) plans every event BACKWARD from its own date. `lib/production/runway.ts` is pure and self-checked (`npm run check:runway`): it takes facts in and returns lanes, six dated checkpoints, and the collisions between two events whose load-in windows touch. Every checkpoint is a row that already exists — zones, liked images, a design document, an issued quote, an export — because this codebase has twice learned what a status somebody must remember to set is worth: the "meeting was held" switch nobody flipped, and procurement's refusal to accept typed usage. **`events.confirmedAt` is the exception and it earns it:** "the client said yes" is derivable from nothing, it is the line between selling and producing, and its absence was not a gap but an active bug — `fetchProcurement` read a SENT QUOTE as commitment and ordered stock for events no client had agreed to. A sent quote is not a reason to buy flowers either. Lanes are a FILTER, never columns: one lane at full content width, and nothing on that screen scrolls sideways.
  - **Cost is not price, and `check:costs` enforces it.** `products.unitPrice` is what the CLIENT pays and feeds the quote; `products.costPrice` is what the STUDIO pays. They sit two fields apart in one drawer. `npm run check:costs` scans `/present`, `app/client`, `app/meeting` and `app/(app)/outputs` for any reference to `lib/suppliers/`, `costPrice`, the margin or the forecast, and fails if one appears — `app/(app)/outputs` is in that list because it is a PRINTING surface. The margin figures therefore never go near outputs (the drawer's margin card was removed; `git show a3e5a4d:app/(app)/dashboard/event-margin-card.tsx` if it comes back — to the drawer, not to outputs).
  - **The base library is copied, not shared (`lib/catalog/standard/`).** The standard tables every hall owns ship with the app as data, and each studio gets its OWN rows — installed at sign-up, and `npm run catalog:standard` backfills a studio that predates them. Nothing crosses organisations: a placement always points at a row in its own studio, and the price and stock count are the studio's, because one designer owns their tables and the next rents them. Ids are UUIDv5 over (organisation, item key), which is what makes re-running the install add only what is new and never overwrite a row the designer has since renamed or priced — the library seeds a catalog, it does not own it afterwards. Adding items is editing an array in `items.ts` (+ `npm run check:standard`); **never renaming a `key`**, which mints a second copy of the same table in every catalog. Changing how an existing item is DRAWN is the one thing the install cannot deliver — that needs `npm run catalog:standard -- --redraw`, which overwrites `appearance` on rows that already exist and no other column. The base tables draw EMPTY (`content: "none"`): on a true-scale plan the shape already says which table it is.
  - **A flower arrangement's spec is rows, not a note (`Product.flowers`, `lib/catalog/flowers.ts`, `check:flowers`).** A `סידורי פרחים` product carries `FlowerLine[]` — flower name × stems per arrangement — edited in the drawer's "מפרט פרחים" section (migration 0011, `products.flowers` jsonb, applied). **The stem count is derived from it:** when rows exist the drawer writes their sum into `categoryFields.stems` and never asks for it; a bare typed total survives only on an arrangement with no rows. Downstream reads go through `stemsOf`, and the rows ride along as a breakdown: the packing list prints "ורד ×240 · פיאוני ×100" under the stem total, procurement fans an arrangement out into one consumable line PER FLOWER under the arrangement's own supplier (`derived:<variant>:flower:<line>`, replacing the single "גבעולים · …" line), the CSV exports a "פרחים" column. `CategoryDef.flowers: true` is the switch and it requires the category to own the `stems` field — flip it on for arches or chuppahs if a studio ever specs them by the stem. **Shades of an arrangement are its variants**, the existing "גוונים וצבעים" list (one swatch per palette, a placement picks one); a per-flower colour was deliberately left out because it would contradict the variants on any arrangement stocked in two palettes. Round items (`usesDiameter`) also ask their diameter inline beside the height now — the same number the appearance modal edits, not a second one.
  - **Shapes are derived from width × depth (`lib/studio/footprint.ts`, `check:footprint`), and parts ADD, never subtract.** The hollow shapes are their own members of `MapShape`: `arc` (a piece of a circular ring, ≤330°), `oval-ring` (אליפסה חלולה — a stadium band; `RingSpec` = band width, gap width, gap at left/centre/right of the bottom run), `horseshoe` (פרסה — the half cut along the short axis, open on the left where the wall is; its gap is how far the bottom leg stops short of the wall, `gapAt` unused) and `rounded-u` (צורת ח מעוגלת — the half cut along the long axis: the straight run on top, a quarter arc down each side to the wall; no gap at all, its sides are the arcs). An oval's gap is ≥60cm or exactly 0: closed, drawn as a keyhole (the two caps coincide, so one outline renders the hole and a hairline marks the hatch) — the arc still never closes. `stadium` (קפסולה) is the solid capsule. A circle part dropped inside a bigger circle does not cut a hole — that attempt produced a solid ⌀4.8m disc named "בר עגול 450x450" in the user's catalog. The user's three curved bars (oval with a 184.5 opening, פרסה with an 80cm entrance, and the top half as a rounded ח) are `oval-ring`/`horseshoe`/`rounded-u` rows with the band = the 60cm module depth and the counter as parts; stretched on the plan they gain straight run and keep the band. Hall features placed from the catalog carry `ring` through like `arc`.
  - **The placement map prints as a production SET, not one drawing** (`/outputs` → מפת הצבה, `outputs-screen.tsx`): a cover with the index, every ticked layer for every zone (grouped by layer, then zone — handed out by trade), the stage build, a table DETAIL per chosen design kit, and the kit schedule — one print, one PDF (browser print; ADR-9 stays cancelled). **One sheet per zone** (`lib/outputs/zone-sheets.ts`, `check:zone-sheets`): each framed on its own zone, each item on exactly one sheet (its zone, else the nearest), the doc filtered never renumbered. **Kits** (`lib/outputs/table-kits.ts`, `check:table-kits`): numbered units with identical dressing share a Hebrew letter, figured over the WHOLE event so ב is ב on every sheet; the letter rides under the table number on the plan, and a detail sheet (`table-detail.tsx`) draws the kit once at 1:10–1:40 with numbered callouts — one per kit, not per table; head tables, blocks and real arrangements are suggested. **Setting-out chains** on the hall sheet are derived from table centres (`lib/outputs/setting-out.ts`, `check:setting-out`) and refuse a scatter. Text inside a drawing is sized in PRINTED mm through `SheetFrame`'s `(denominator) => …` children — never author a label in room mm. The drawing is clipped to the frame. Number ranges in Hebrew lines are wrapped LRI…PDI (`formatTables`) or the bidi algorithm prints 1–5 as 5–1. **Measurements are data** (`lib/outputs/measurements.ts`, `check:measurements`): overall, chains, sizes (every side of a SHAPED stage, width × depth otherwise), two wall ties per element, gaps to the nearest table/element (<1.20 flagged ⚠), one aisle per distinct row/column width — which kinds a sheet draws is `PlanSheet.measure` (hall: sizes + chains; תוכנית מידות: all). Every figure goes through `placeLabels` (`lib/outputs/labels.ts`, `check:labels`), which steps off door swings, furniture and other figures — never draw a dimension label by hand. Orientation `auto` gives each drawing sheet its own paper via CSS named pages (`sheet-portrait`/`sheet-landscape`), chosen by `sheetScale`. Chairs are drawn BEFORE tables, inside ONE floor stack painted in the studio's order with `autoStack` applied to the whole floor at print time (a table on a stage is always painted over it — the studio only restacks on a drag). **What stands on a stage is measured off the stage**, not the room: chains from its edges to its tables (on whichever side is clear and in the room, else inside the stage along the band before the first row), ties from other items to its edges. Ties stop at the first element in the way; a rectangle's width/depth go on its OPEN sides; element outlines are exact shapes no offset figure may sit on, and a figure tries both sides of its line before going past an end. Vertical figures are rotated to read up the line. The title block is five two-line cells with auto-fitted text (the seat count rides on the scale band). **A table may name its chair** (`DesignTable.chairVariantId`, `setTableChair`, `lib/catalog/chairs.ts`; absent = the studio's default, the first `chairs` row): the chairs sheet names chairs per table only when they differ, and the packing list now packs every table's seats as its chair (`packingList(…, chairOf)`) — deliberately NOT in `measureTotals`, so the quote is unchanged.
  - **Procurement is derived, never typed.** `lib/suppliers/procurement.ts` reduces the drawings in a date window; there is no "how much did I use" input anywhere and there must not be, or it will drift from the plan that produced it. The one idea in that file: a monthly *sum* is wrong for most of the catalog, so `Product.stockKind` picks the reduction — `consumable` summed, `owned` peaked against `stockQty` on its busiest single day, `rented` listed per event. Only events with an `issued_quotes` row feed the order; undrawn, unmeasured and unquoted events are counted and stated on screen rather than absorbed.
  - **A stage is ONE placement; its decks are derived (`lib/design-document/stage.ts`).** `Placement.stage` holds an outline (in the placement's own frame), the front edge, and which deck variants it may use — never the decks. The canvas seams, the quote, the packing list and procurement all lay them through `layStage` (via `MeasureContext.deckOf` in `measureTotals`), so resizing the outline re-derives the build and there is no stored copy to drift. A stage is built from every rectangular, unarchived product in `stages` AND `stage-decks` — the studio's own platforms (a 400×300 it owns) are real building pieces, largest first; the designer narrows the set in the fill tool's "אילו במות". Don't restrict it back to `stage-decks` only: the user explicitly asked for their own stages to be used. The fill (`lib/studio/stage-fill.ts`, `check:stage-fill`) lays rows from the front so leftover lands at the back, never mixes deck families (different height, or no shared 10cm module), and allows 5cm tolerance because wall-snapped areas are never whole metres. Always lay in the stage's OWN frame, then carry out into the room — laying in world coordinates makes a mirrored stage a different build. "פירוק לפלטות" (explode) is the one-way escape hatch to loose decks. A stage also carries its `heightMm`, raised `levels` (they PARTITION the floor with the base — each laid at its own height inside its own outline and the stage's — never stacked), and `stairs` (edge + position + width; the step count is derived from the rise — ≤18cm risers, 28cm treads — unless the designer set `risers` on the flight). Skirt metres are the open edges (not within 30cm of a wall), and stairs and skirt reach the quote through `stairsVariant`/`skirtVariant` — rows in the `stage-stairs`/`stage-skirts` categories. Railings are a studio setting (`studio_settings.stage_railing_above_mm`, null = off, settings → במות), never railing the front. The "תוכנית במה" sheet on /outputs prints the build with decks numbered front to back. Drawing is kept clean by `lib/studio/stage-draw.ts` (`check:stage-draw`): sides held to 45° steps from the first side (itself squared to the nearest wall, or to the stage when drawing a level) and their lengths pulled to what the decks build exactly (`lengthSnapper` in stage-fill.ts — every sum of deck sides, so 244×122 sheets pull to 3.66/4.88/…), else whole 10cm, Alt frees, a typed number + Enter lays an exact length in cm, near-square outlines are squared on close, self-crossing ones refused. **Never snap a stage to a fixed module** (a 244×122 sheet has no 10cm one — that is how 4.88 became 4.90 and stopped fitting): resize and outline grips pull to `lengthSnapper` lengths within a few pixels and are otherwise exact to the cm (Alt lets go), and the stage bar's "מידות" takes an exact typed size. "עריכת הבמה" edits the outline itself (`OutlineHandles` in canvas-stage.tsx: drag corners/sides, double-click a side to split it, a corner to remove it — `moveVertex`/`pushSide`/`splitSide`/`removeVertex`/`cleanOutline` in stage-draw.ts); on commit, edge items are carried by where they stood (`rehomeEdgeItems`), never by side number. Delete with stairs/a banquette picked out removes THAT item, not the stage under it. A stage's outline must stay CENTRED on its box (custom footprints draw about their box centre) — any outline edit goes through `reframeStage`. Stages pushed together are joined with `stickBoxes` and merged with `mergeStages` (one outline, so the skirt never runs along a seam). A stage product dropped from the rail becomes a stage (`asStage` in the studio screen). **Every open stage edge is finished** (`StageStair.kind`: stairs — the default on every open side of a new stage — `bench` (בנקט, a seat-deep strip outside the edge, seats one per 60cm, and a surface: design items dropped on it carry `Placement.perch` and spread along it; removing the stage removes them, copying it copies them) or `barrier` (on the edge, inside the outline)). `edgeGaps` finds what nothing covers; never let a stage be created with bare open edges. The `stairs` array name is historical — it holds every kind, now five: also `backdrop` (a wall on the edge; allowed against the venue's wall) and `ramp` (1:12, length derived from the rise). Corner pieces where two runs of stairs/banquettes meet are derived (`stageCorners`, off with `corners: false`), and quoted. A stage may carry `surfaceVariant` (category `stage-surfaces`, priced per m² of `stageAreaMm2`). Stages save as templates in `studio_settings.stage_templates` (migration 0009, applied) via `lib/settings/actions.ts`, placed from the stage tool's draw-phase bar. A selection made only of stages gets the stage-group bar (merge first), not the generic group bar. **Drawn or laid by hand, it is the same stage:** a piece becomes a stage through `stageFromPiece` (faced away from the wall, like a drawn area), `mergeStages` re-frames a merged rectangle into the canonical front-first one and re-homes edge items by the stretch they covered, then `tidyEdgeItems` makes one run per side and kind (no double-counted flights). `check:stage` builds a 6×4 both ways and asserts they match — keep it passing. Stages pushed flush but not merged judge their edges with `besideNeighbours` (a shared side is not open) and `trimSeams` removes items on it. A banquette is set like a head table (`StageStair.seats`, default one per 60cm, 0 = none): its chairs stand BEHIND it on the stage, tucked under its inner edge and facing out over it, counted in the seating readout, packed as the studio's first `chairs` row. Edge items are quoted by their own rows (`stairsVariant`/`benchVariant`/`barrierVariant`, falling back to the studio's first row of `stage-stairs`/`stage-benches`/`stage-barriers`), stairs counted per stair-module width. A studio with no decks gets them installed by the stage tool itself (`installStageBasics` — deck/stairs/skirt keys only, never the whole base library).
  - **Google Calendar is two one-way syncs, not a two-way one (`lib/google/`).** The diary is PUSHED into a calendar the app creates inside each designer's Google account; their own calendars are PULLED back as read-only busy blocks. Each side owns its own entries, so there is no conflict resolution and none should be added — a real two-way sync needs watch channels that expire weekly and a scheduler to renew them, which this app deliberately does not have. **Per USER, not per studio**: the diary is shared but a Google account is a person's, so `google_event_links` is keyed on (connection, appointment) — one appointment pushed to three members is three Google events, and keying on the appointment alone orphans two of them beyond reach. `lib/google/sync.ts` is a plain module on purpose (like `lib/db/revalidate.ts`): "push to every connected calendar" must not be a POST endpoint. The push is **best-effort** and records failures in `google_connections.last_error` rather than throwing — the meeting is already committed and the designer's screen is already right. Off until four env vars are set, same seam shape as R2 (`lib/google/config.ts`). Scopes stay narrow: `calendar.app.created` writes only the app's own calendar and never the primary one. The pull reads `minAccessRole=writer` so Google's holiday feeds don't flood a grid this app already annotates from `lib/calendar/hebrew.ts`. Deleting an appointment must read its links BEFORE the delete — the FK cascades.
  - **`lib/meeting/` and `lib/appointments/` are two different things.** `lib/meeting/` (singular) is the guided *flow* — which stages exist, in what order, configured per studio. `lib/appointments/` is the **diary**: a scheduled sit-down with a client, on a date, on the dashboard calendar. It is called an "appointment" in code and a "פגישה" on screen precisely so `lib/meetings/` never gets created one character from `lib/meeting/`. An appointment's `eventId` is **nullable on purpose** — the first meeting happens before there is an event, and an event normally collects several (docs/01 §מצב פגישה). It replaced `events.meetingDate`, a column that could hold one meeting per event and that no form in the app ever wrote; don't re-add a date column to `events`.
  - **Schema changes are generated migrations now, not `db:push`.** Edit `schema.ts` → `npm run db:generate` → `npm run db:migrate`, and commit the `.sql`, its snapshot and `drizzle/meta/_journal.json` together. Neon holds data worth not losing, and `push` reaches a schema without recording how it got there. Pointing `push` at Neon desynchronises `__drizzle_migrations` from reality, after which the next generated migration diffs against a snapshot that describes nothing. Deploying does **not** apply migrations — that is `db:migrate` with `DIRECT_URL` set to Neon's *direct* host (a migration through the pooler hangs with no error to read).
  - **Saved sketches are rows, not a settings list (`sketch_templates`, `lib/studio/sketch-actions.ts`).** A whole design document under a name — saved from the studio toolbar's סקיצות panel, loaded back into any sketch (in place: one `loadDocument` history entry; or added: re-id'd through `pasteInto`), and offered in the new-event form, where `beginEvent` seeds the event's v1 from it server-side. `adoptSketch` (`lib/studio/sketches.ts`, `check:sketches`) drops drapes and feature arrangements when the sketch is loaded into a different venue — they name that venue's walls. Migration 0010.
  - **The floor stack settles itself after a drag (`autoStack`, `lib/design-document/stacking.ts`).** The smaller thing stands on the bigger one: a table carried onto a stage goes above it, a stage dragged over tables leaves them on top — folded into the drag's own undo entry. While dragging, the cargo is painted last (`lifted` in canvas-stage) and the planes the gesture cannot be about are dimmed (`autoPlane`), the same way choosing a plane on the toolbar dims the rest. Restack by hand with Ctrl+] / Ctrl+[, the bar's menu, or the canvas's right-click menu.
  - **Multi-select on the sketch:** the rubber-band takes what it TOUCHES; Shift adds, Ctrl/Cmd toggles (so a band can take things out), Ctrl+A selects everything with a place of its own. The hall editor still encloses.
  - **A label goes to `labelAnchor`, never to the box centre (`lib/studio/label-anchor.ts`, `check:label-anchor`).** A table's number and capacity, a placement's name or icon, the catalog preview and the rail's drag image all put their text at the shape's visual centre: the deepest point inside the outline, and of the points that deep the one nearest the centroid, settled onto the band's mid-line. On a rectangle or a round that IS (0,0); on an arc it is the middle of the band at the apex, where the box centre is in the air the ring curves round (a crescent head table used to wear its number across its inner edge). In the footprint's own frame, so the studio carries it inside the table's `<g>` and the printed map goes through `tableLabelPoint` (components/footprint-shape.tsx) to get the same point in plan millimetres. Product colour goes the same way: `productStyle` in that file merges the catalog row's appearance style under a table's own, and every surface that draws a footprint reads it — the canvas used to draw every placed item white whatever the appearance editor said.
  - **Design items are drawn as their category, not as outline + icon (`lib/catalog/symbols.ts`, `components/item-symbol.tsx`).** Candlesticks (candles round a stem, count = `categoryFields.arms`; a long one is a row on a bar), flower arrangements, centrepieces, chairs (seat + backrest, back = −y), sofas (back, arms, cushions), chandeliers (lines only — overhead), columns, fountains, arches, chuppahs, bars. Derived from category + size + shade; one opt-out per row, `MapAppearance.symbol === false` (the appearance editor's switch), which brings back outline + name/icon. Only a circle/ellipse/rect footprint is drawn this way — a ח bar or a hand-drawn outline keeps its outline. Every surface that draws a footprint draws the picture: canvas `PlacementNode`, the rail's `PlanGlyph`, `AppearancePreview`, the appearance modal's canvas, and the printed map (`print`: white fills, ink lines). Same file: `ClothDrape` (a worn cloth is fabric 9cm past the tabletop with a hem and folds — a round-joined stroke, so any shape; the table's own edge goes quiet under it), `DrapePleats` (curtains) and `RugPattern` (border + fringe on the short ends, `rugs` only). Any placed item of a fixed size can be drawn bigger/smaller on one plan (`Placement.scale`, `setPlacementScale`, 30–300%, the bar's "גודל על התוכנית") — a DRAWING size; quote, packing list and orders never read it.
  - **Catalog textures and the default image (`lib/catalog/textures.ts`, `MapAppearance.texture`).** The venue floor materials (`SurfaceFill`, components/surface-fill.tsx) plus `wood` and `marble` — catalog-only, NOT added to `SURFACE_MATERIALS`, so the hall editor's list is unchanged — fill an outline-drawn item (tables when bare, stages from their deck's row, bars, rugs, decks, "other"; never a symbol item or anything overhead), tinted by the shade/fill. **Every shape is its own layer**: `MapAppearance.texture`/`textureImage` surface the BASE shape only, and each `ShapePart` carries its own (`surfaceLayers` in lib/catalog/textures.ts, by piece index — `composeFootprint` emits base first, then parts in order); none inherits another's. `textureImage` is a picture the designer uploads (`lib/files`, kind `product`), `tile` at a real repeat size or `stretch` over its shape, winning over `texture`. Everything draws through `ItemSurface` (components/surface-fill.tsx) OVER the flat fill, with the edge stroked again on top. Picked with `SurfacePicker` (app/(app)/catalog/surface-picker.tsx) — the editor's side panel for the main shape, the "טקסטורה" chip on each added shape's bar — and drawn on the editor's own canvas too. Stages and decks are NOT textured (the user asked for them empty; their 11 rows on develop were cleared 2026-10-09). An item with no photo shows `AppearancePreview` as its image (`ProductImage` takes the whole `product`): the plan drawing itself — a table with its chairs, a cloth as cloth, a drape as a pleated band — on a dotted plan tile. **Chairs have styles** (`MapAppearance.symbolStyle`, `ChairStyle` in lib/catalog/symbols.ts: dining, chiavari, crossback, ghost, folding, armchair, stool, bench), picked in the editor; the chairs round every table are `SeatChair` (a neutral dining chair) on canvas, print and catalog preview. A table's chairs are still counted by its `seats` multiplier — there is no per-table chair product yet, deliberately (it would double what procurement orders).
  - **An added shape may be drawn by hand** (`ShapePart.shape === "custom"`, its `outline`/`edgeCurves`, recentred on its box at `x`/`y`): the editor's אלמנט flyout has "צורה חופשית", and every part's bar has "עריכת הקווים", which hands the part's placed outline (`placedPartOutline`, lib/studio/footprint.ts) to a SECOND `useOutlineEditor` while the base one's Ctrl+Z steps aside; "סיום" writes it back with the turn baked into the points. Resizing a hand-drawn part rescales its outline (`patchedPart` in appearance-modal.tsx).
  - **Canvas speed.** The plan re-renders every node on each pan/zoom frame (layers get the live zoom), so: the drawings (`ItemSymbol`, `SeatChair`, `ClothDrape`, `DrapePleats`, `RugPattern`, `SurfaceFill`) are `memo` with `sameDrawProps` (footprint compared by value); wheel steps are gathered and applied once per animation frame (`wheelAcc` in plan-canvas.tsx); and while the view moves the `<svg>` carries `data-moving`, which turns off the textures' `feTurbulence` grain (`.plan-grain` in globals.css) until ~200ms after the last step. Keep new heavy drawings memoised and new noise filters under `.plan-grain`.
  - **The studio canvas writes no table numbers and no `4/12`** — removed at the user's request (single tables and groups). They are on the table's bar in the inspector, and the PRINTED placement map still writes the number (the crew finds tables by it). Don't put them back on the sketch.
  - **Items on a table have real places (`lib/design-document/dressing.ts`, `check:dressing`).** `Placement.position` on a table item is an offset in the TABLE'S OWN FRAME (before its turn and mirror), read only when `DesignTable.arranged` is set; otherwise `autoLayout` places them every draw (biggest centred, the rest in a run along a long table or ringed on a round one). Everything reads positions through `dressingSpots` (components/footprint-shape.tsx) — canvas and printed map — never the old 840mm column. Double-click a table (or the bar's paint-roller) opens its **focus mode**: framed, the room behind a scrim (click it or Esc to leave), items draggable in the table frame (clamped to the top, snapping to the centre lines, a selection moves together), and `DressingBar` (dressing-bar.tsx) at the top with center/row/column/ring/auto. Arrow keys nudge the selected items 1cm (Shift 5cm) in SCREEN direction, carried into the table frame. A held item snaps to the centre lines, into line with another item, or to its MIRROR across the centre (symmetric pairs), with the snapped line drawn solid. Any drag or arrange sends EVERY item's place in one `arrangeDressing` so an auto table freezes without jumping; `resetDressing` goes back to auto. A drop onto the dressed table or an arranged one lands where it was let go. `copyDressing` replace carries `arranged`.
  - **A runner is not the table's cloth (`isRunner`/`anchorOf`, lib/catalog/categories.ts).** It is filed under `tablecloths`, but a strip (≤70cm wide, ≥2.5× as long; a row with no size is read by its name) resolves to anchor `free`: an item ON the table, so it never replaces the cloth (`coverOn`, the drop path, the cloth swap list) and is drawn over it as the `runner` symbol. `dressingSpots` lays it apart from the others — centred, along the table's long side, first (under them), trimmed to the table's length plus `CLOTH_DROP_MM` each end (`DressingSpot.footprint`) — and the arrange actions leave it alone. Everything that clamps an item on a table reads `DressingSpot.box` (in the table frame, turn included), not `chipBox`.
  - **Apply to tables in a pattern (`lib/studio/table-patterns.ts`, `check:table-patterns`, `table-pattern-picker.tsx`).** all / same type / zig-zag (checkerboard) / alternate (by number) / alternating rows / columns / selected — rows and columns are CLUSTERED from where tables stand, and every pattern is read relative to the SOURCE table ("the half this table is in"; "החצי השני" is the other half — dress A, apply; dress B, apply the other half). The picker shows a mini-map with the targets lit before applying. One item goes through `applyToTables` (recolouring other shades of the same product, never a second copy) — and may alternate TWO shades, split by zig-zag/number/rows/columns relative to the source (one `applyToTables` per shade, one `batch`); a whole table through `copyDressing` replace/add.
  - **Saved table designs (`TableDesign`, `studio_settings.table_designs`, migration 0012 — applied to `develop`, not yet `main`).** A table's whole dressing (cloth included) with quantities, positions and `arranged`, saved/applied from the "עיצובים שמורים" chip on the table bar and the dressing bar (`table-designs-panel.tsx`, `saveTableDesign`/`fetchTableDesigns`/`deleteTableDesign` in lib/settings/actions.ts). Applying is the `dressTables` action, which shares `wearDressing` with `copyDressing` — one set of rules (one cloth per table, exceptions, arranged carried over). To lay a design across the room: put it on one table, then that table's pattern.
  - **Ceiling rods are gone** (removed at the user's request: the whole `CeilingRig`/`RigHang` feature, the /halls מוטות mode, and snap-to-line). A venue structure stored with a `rigs` key is simply ignored on read. Don't bring them back.
  - **What is still `localStorage`, and stays there:** which event and which venue this *device* has open, and the scratch drawing made before any event exists to attach it to (`lib/studio/storage.ts`). Per-device UI position, not studio data — see the note in that file before "finishing the migration" by deleting it.
  - **A version is not a save.** The studio autosaves every 500ms, so autosave UPDATES the current `design_documents` row; a new version is minted only when an output *seals* it (`sealDocument`, [lib/studio/actions.ts](lib/studio/actions.ts)). A sealed row never changes again, which is what makes F-7.4's "העיצוב השתנה" a comparison of two integers and keeps the drawing a quote was made from on disk.
- **Two ladders, and venues are per-member:** a `StudioRole` (owner/designer/crew, [lib/team/types.ts](lib/team/types.ts)) says what you see of the *business*; a `VenueGrant` (viewer/editor/manager, [lib/venues/access.ts](lib/venues/access.ts)) says which *properties* you may open and at what level. The owner reaches every venue; everyone else reaches only granted ones. So a venue query scoped by `organizationId` alone is a bug — go through the helpers in [lib/venues/actions.ts](lib/venues/actions.ts) (`requireVenueAccess`, `grantedVenueIds`). A `guest` grant never conveys events, clients or prices; `npm run check:access` asserts that line.
- **Server actions:** `currentOrg()` for tenant scope, `currentActor()` when the answer differs between members of one studio. User-correctable failures return `{ error }` (Next redacts thrown messages in production); authorization failures throw.
  - **Files go through `lib/files/`, never through a server action.** `uploadFile(file, kind)` asks for a ticket and PUTs the bytes straight to storage; the app stores the returned URL. R2 when its five env vars are set, a local folder (`.uploads/`, served by `app/api/files`) otherwise — the swap is one branch in `fileDriver()`. Keys are minted server-side as `<organizationId>/<kind>/<uuid>.<ext>`: the prefix is the tenant boundary and the extension comes from an allowlist (no SVG — it executes where it is served; no PDF — ADR-3 stays cancelled).
  - **Debounce anything that autosaves.** Against `localStorage` a write per keystroke was free; against Postgres it is a request per character. The studio sequences its writes (one in the air at a time, newest queued) — see `flush()` in `app/(app)/studio/studio-screen.tsx`; the spare field and the settings form debounce.
