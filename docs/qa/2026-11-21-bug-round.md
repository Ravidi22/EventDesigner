## 1. Curtain and rod (CR)

### CR-1 · SEEN works here — a curtain dropped on a bare rod hangs on it
On this branch, every case adopted the rod:
- a rod in the open, curtain dropped on its middle;
- a rod 66 cm in front of a wall;
- a drop near the rod's end.

The drawing read back shows the rod placement turned into the curtain, with the same rail.

**Likeliest cause of the report:** §0 (production). Other ways it still fails here:
- **A wall or tall side is nearer than the rod** (CODE, `curtainDrop`, lib/studio/rail.ts:798-822). The nearest of rod / wall / side wins, and a rod only counts within 80 cm. A drop 90 cm off a rod that stands near a wall goes to the wall.
- **The rod is not "bare".** These never take a curtain:
  - a curtain's own rod;
  - a rod that already has a curtain;
  - a venue rod drawn at /halls ("וילון על מוט" is a curtain feature, not a bare rod).

### CR-2 · CODE — no feedback while DRAGGING a curtain over a rod
The armed click lights the rod it will take (canvas-stage.tsx:6036-6044). A drag from the rail shows nothing, because `dropSnap` returns null for wall items.

### CR-3 · CODE — a selected rod offers no curtain
`swapClass` is `layer|anchor|sizing`. A rod is `ceiling|wall|fixed` and curtains are `ceiling|wall|stretch`, so the swap picker never lists a curtain for a rod (studio-screen.tsx:240-243).

### CR-4 · SEEN (low) — dragging a rod leaves `placement.position` behind
The posts move; `position` stays where it was dropped. Nothing in the adopt path reads it, but any reader of `position` for a rod is wrong.

### CR-5 · CODE — the rod row stays armed
A second click on the rod lays a second bare rod on top of the first. In the test, an armed curtain clicked on an already-curtained rod laid a new curtain with its own rod beside it.

### Ravid's direction
- Draw a LINE, then hang a curtain on it.
- Also a FIXED rod that can be dragged without limits.

**What exists today:**
- `RodDrawPane` (click per post, Enter ends, 45° steps, typed cm, also a press-drag mode) is reached only from a placed rod's or curtain's bar ("ציור המוט מחדש" / "ציור על מוט").
- Arming the row drops a straight 3 m rod.
- A rod's body already drags freely (no snap, no limit).

## 2. Stage edge items and banquettes (EI)

### EI-1 · SEEN — the sofa is always centred on its banquette; pressing it slides the whole banquette
- **Data:** `BenchSide.widthMm` is "centred on it" (types.ts:275-287). No offset is stored. `benchLayout` centres it (bench.ts:252, 302-322).
- **Interaction:** no sofa grip exists. A press on the sofa slid the banquette along the side; t went 0.15 → 0.283, flush to the stairs.
- **Tables:** no code relates a banquette to the tables in front of it.

### EI-2 · CODE — banquettes at an INSIDE corner stand through each other
`edgeJoints` mitres only stairs. A banquette gets "flush" only when dead straight and of equal depth (stage.ts:1188-1218).
- An outside corner does get a corner piece. SEEN: the front-right banquette and the side banquette meet in a filled square.
- Banquettes on two flush stages join only when collinear (`joinEdgeRuns`). A ר across two stages is never joined.
- A stage banquette and a free banquette never join at all.

### EI-3 · SEEN (HIGH) — Ctrl+C with a banquette picked copies the WHOLE stage, and Ctrl+X cuts it
- **Seen:** banquette picked (bar "בנקט · בחזית"), Ctrl+C said "הועתק פריט", Ctrl+V pasted a second stage.
- **Ctrl+X:** CODE. It is unguarded (studio-screen.tsx:5267-5273) → `cut()` removes the whole stage. Ctrl+D and Delete are guarded by `activeEdge`; C and X are not.

### EI-4 · SEEN (HIGH) — right-click on a picked edge item shows the STAGE's menu
Its "שכפול" and "מחיקה" act on the whole stage. Delete on the keyboard removes only the item.

### EI-5 · SEEN — an edge item's bar has no copy and no "…"
Stairs: width · risers · delete. Banquette: width · chairs · delete. There is no way to copy, duplicate or flip one stair or banquette.

### EI-6 · SEEN — a neighbour is cut back but never grows back
- Stairs typed 120 → 240: both banquettes cut 240 → 180.
- Stairs typed back to 80: the banquettes stay 180, leaving two bare gaps.
- No path grows a neighbour. `shareSide` only cuts, splits or drops (stage.ts:1906-1947). A slide stops flush and never pushes.

### EI-7 · SEEN — shrinking a stage leaves its edge items overlapping
The stage was typed 600 → 240 wide. Every item kept its `t` and width and was clamped on its own (`itemSpan`), so they stand through each other. Stage resize paths never run `shareSide` / `tidyEdgeItems` (studio-screen.tsx:3296-3329, 5832-5837).

### EI-8 · SEEN — the stage's rotate knob and middle grip sit ON the front-centre stairs
With the stage selected, the second click meant to pick the stairs hit the knob. A typed figure then went to the STAGE's width.

This breaks the rule "never draw a handle where something painted later can cover it", the other way round: here the handle covers an item.

### EI-9 · CODE — the banquette DEPTH grip writes the legacy field
`onChange({ ...st.item, depthMm })` (stage-edge-handles.tsx:468), while the panel writes `bench.depthMm`, which wins (bench.ts:121). Once a depth was typed, dragging the grip moves only the readout.

### EI-10 · CODE — splitting a banquette round a flight copies its whole spec onto both pieces
Typed seat counts and the sofa are duplicated (stage.ts:1940-1943). The result is two centred sofas, and 8 chairs become 5 + 5.

### EI-11 · CODE — a banquette cut back or dropped by another item leaves its perched dressing behind
Affected paths: `pickStair`, `changeStair`, `onEdgeItemChange`, level removal.

### EI-12 · CODE — two undo entries for one edit
`removeStair` and a kind change call `batch(…)` and then `patchStage`. Ctrl+Z brings the banquette back without its dressing.

### EI-13 · CODE — a typed flight width resizes about its centre
A flight that ran into a corner leaves it, and the corner piece goes.

### EI-14 · CODE — a copied stage whose banquette is in a joined run draws that banquette invisibly
Edge-item ids are kept on copy, and the joined-run skip is keyed by item id only (edge-runs.ts:144-146, canvas-stage.tsx:5184).

### EI-15 · CODE (low) — "fill open edges" appends without tidying
A banquette filled beside another on the same side stays two items, each with its own layout.

## 4. Material (MT)

There is no material field. A material is guessed in eight places:
1. `frameOf` (items.ts:195): pale tone → crystal, else metal.
2. `armMaterial` (items.ts:103): pale tone → glass arms.
3. `METAL_SHADE` (items.ts:893): a metal word in the shade's NAME.
4. `vesselForm` (items.ts:874-890): by the product's name.
5. `glassFinishOf` (chandelier.ts:86-92): by name and swatch.
6. `frameMaterial` (overhead.ts:113): pale → glass.
7. The bar counter (floor-kinds.ts:674): by `pale(tone)`.
8. Plan side: `armLine` / `paleTone` (item-symbol.tsx:508-520) and the pale chandelier and bare arch drawings.

The only explicit material is the chuppah's `ChuppahFinish`.

### MT-1 · CODE — a white or cream vase is built as CLEAR GLASS
`pale(tone) && !METAL_SHADE → glassMaterial` (items.ts:946). A gold colour typed in the editor comes out glazed, not metal, because metal is read only from the shade's NAME.
